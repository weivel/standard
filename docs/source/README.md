The repo root of the weivel standard: one CMake project in C11 that builds the library in four forms (`weivel_standard`, a static library; `weivel_standard_shared`, the shared library with the public symbols exported and the rest hidden; `weivel_standard_testing`, a build whose allocator counts blocks and can fail on demand, used by the memory tests; and `weivel_standard_undescribed`, the objects `weivel-describe` links, since the descriptions it writes are part of the full library), the `weivel-describe` program and, when this is the top project, the tests. It builds nothing of the core on its own: unless a `weivel_core` target already exists (as when the kit or another project adds the standard), configuring refuses to start without a core checkout at `siblings/core` (a clone, a directory junction or a symlink) or the one `-DWEIVEL_CORE_SOURCE_DIR` names, and adds it as a subdirectory. Nothing checks that checkout against the commit `repo.json` pins, so building against the pinned commit is the builder's to do. Every target is built with warnings as errors (`/W4 /WX /utf-8` on MSVC, `-Wall -Wextra -Wpedantic -Werror` elsewhere), the program lands in `build/bin` (in `build/bin/<Config>` under a multi-configuration generator such as MSVC, since only the unsuffixed output directory is set) and the shared library's import archive in `build/shared`. The descriptions of the standard's definitions that other definitions nest are generated at build time by `weivel-describe` (see [the descriptions doc](../descriptions.md)). Build and test with `cmake -S . -B build`, `cmake --build build --config Debug` and `ctest --test-dir build --output-on-failure -C Debug`; the program is `build/bin/weivel-describe`, whose usage it prints when a required option is missing.
