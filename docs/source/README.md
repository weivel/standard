The repo root of the weivel standard: one CMake project in C11 that builds the library in four forms (`weivel_standard`, a static library; `weivel_standard_shared`, the shared library with the public symbols exported and the rest hidden; `weivel_standard_testing`, a build whose allocator counts blocks and can fail on demand, used by the memory tests; and `weivel_standard_undescribed`, the objects `weivel-describe` links, since the descriptions it writes are part of the full library), the `weivel-describe` program and, when this is the top project, the tests. It builds nothing of the core: configuring refuses to start unless the core is checked out at `siblings/core` (a clone, a directory junction or a symlink, at the commit `repo.json` pins) or `-DWEIVEL_CORE_SOURCE_DIR` names one, and adds it as a subdirectory so the standard compiles against the very core it is pinned to. Every target is built with warnings as errors (`/W4 /WX /utf-8` on MSVC, `-Wall -Wextra -Wpedantic -Werror` elsewhere), programs and libraries land in the build's `bin` directory, and the descriptions of the standard's own services are generated at build time by `weivel-describe` from the public headers, once for the config, secrets, paths and log services, once for the scope service and once for the host service (see [the descriptions doc](../descriptions.md)). Build and test with `cmake -S . -B build`, `cmake --build build --config Debug` and `ctest --test-dir build --output-on-failure -C Debug`; the program is `build/bin/weivel-describe`, whose usage it prints when a required option is missing.
